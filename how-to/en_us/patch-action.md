# How to Create `PatchAction` and Inject Existing Pattern Logic

[简体中文](../zh_cn/patch-action.md) **English**

> Generated by GLM-5.1

## Overview

`PatchAction` is a mechanism provided by HexAutomata that allows you to **replace/wrap** a registered HexCasting Action, injecting custom behavior while retaining access to the original logic.

The core idea: combine the original Action with a patcher Action — the patcher executes first, and if it throws specific signals, execution falls back to the original logic or halts the spell.

## Key Classes

### PatchAction

```kotlin
open class PatchAction(val original: Action, val patcher: Action) : Action
```

`PatchAction` holds both `original` (the original Action) and `patcher` (the patch Action), and implements the `Action` interface itself. The execution flow of its `operate` method is as follows:

1. Attempt to execute `patcher.operate()`
2. If the patcher returns normally, use the patcher's result directly
3. If the patcher throws an exception, enter the exception handling branch:
   - Throws `PatchAction.USE_ORIGINAL` → fall back to `original.operate()`
   - Throws `PatchAction.STOP_ALL` → silently halt the spell (no additional effects)
   - Other exceptions → propagate normally

### Two Control Signals

| Signal | Effect |
|--------|--------|
| `PatchAction.USE_ORIGINAL` | Discard patch logic, fall back to the original Action |
| `PatchAction.STOP_ALL` | Completely halt the current spell, executing no effects |

These signals are instances of `NoTraced` — a `Throwable` that does not fill in the stack trace, used for control flow rather than actual errors.

## Registering Patches: HAPatches

`HAPatches` is HexAutomata's built-in patch registry, inheriting from `CustomRegisterObject<Action>`. It uses the Mixin accessor `AccessorActionRegistryEntry` to replace Actions in the registry at runtime.

### How It Works

```kotlin
object HAPatches : CustomRegisterObject<Action>() {
    init {
        // Using HexCasting's brainsweep pattern as an example
        this[HexAPI.modLoc("brainsweep")] = OpExtendBrainsweep
    }

    fun patchAll() {
        for (pair in MAP.entries) {
            val entry = HexActions.REGISTRY[pair.key]
                ?: throw IllegalArgumentException("invalid patch for id ${pair.key}")
            (entry as AccessorActionRegistryEntry).setAction(pair.value)
        }
    }
}
```

Flow breakdown:

1. **Declare patches**: Register mappings with `ResourceLocation` as key and the patch Action as value. The key must correspond to an **already registered** Action, otherwise `patchAll()` will throw an exception
2. **Apply patches**: `patchAll()` iterates all mappings and replaces the Action in registry entries via the Mixin accessor
3. **Replace without losing**: The patch Action is typically a subclass of `PatchAction`, and the `original` parameter should be the originally registered Action being replaced, ensuring the `USE_ORIGINAL` signal can correctly fall back

### Mixin Accessor

```java
@Mixin(ActionRegistryEntry.class)
public interface AccessorActionRegistryEntry {
    @Mutable
    @Accessor(remap = false)
    void setAction(Action v);
}
```

This Mixin makes the `action` field of `ActionRegistryEntry` writable, allowing runtime replacement.

## Practical Example

### Example: Creating a Custom PatchAction

The following example demonstrates how to create a patch for an existing HexCasting pattern, inserting custom behavior before the original logic:

```kotlin
import io.yukkuric.hexautomata.action_patch.PatchAction
import at.petrak.hexcasting.api.casting.castables.Action
import at.petrak.hexcasting.api.casting.eval.CastingEnvironment
import at.petrak.hexcasting.api.casting.eval.OperationResult
import at.petrak.hexcasting.api.casting.eval.vm.CastingImage
import at.petrak.hexcasting.api.casting.eval.vm.SpellContinuation

object MyCustomPatch : PatchAction(
    original = getOriginalAction(),  // Get the original Action
    patcher = MyPatcherAction
) {
    object MyPatcherAction : Action {
        override fun operate(
            env: CastingEnvironment,
            image: CastingImage,
            continuation: SpellContinuation
        ): OperationResult {
            // Custom pre-logic
            if (shouldSkip(env)) {
                // When condition is met, fall back to original behavior
                throw USE_ORIGINAL
            }

            if (shouldBlock(env)) {
                // When condition is met, completely block the spell
                throw STOP_ALL
            }

            // Otherwise execute custom logic and return the result
            return myCustomOperate(env, image, continuation)
        }
    }
}
```

### Registering in HAPatches

```kotlin
// Run after the registration phase (recommended during Common Setup phase)
HAPatches[HexAPI.modLoc("existed_pattern_id")] = MyCustomPatch
```

> **Note**: The `init` block of `HAPatches` is for HexAutomata internal use and cannot be modified. Custom patches should be registered after the registration phase but before any casting occurs; the Common Setup lifecycle event is the recommended place.

### Using via KubeJS

HexAutomata exposes `PatchAction` and `HAPatches` as script bindings through its KubeJS plugin. You can use the control signals directly in KubeJS scripts:

```js
// In server/startup scripts
// Throw USE_ORIGINAL to fall back to original logic
throw PatchAction.USE_ORIGINAL

// Throw STOP_ALL to halt the spell
throw PatchAction.STOP_ALL
```

## Important Notes

- `PatchAction`'s exception handling automatically unwraps KubeJS's `JavaScriptException`, so throwing `PatchAction.USE_ORIGINAL` or `PatchAction.STOP_ALL` from KubeJS scripts works correctly
- Patch registration timing matters — `patchAll()` must be called after the Action registry is frozen but before any casting occurs
- `USE_ORIGINAL` and `STOP_ALL` are not real exceptions; they are control flow signals that won't appear in logs or error reports
