# How to Create Custom `BrainsweepCallback`

[简体中文](../zh_cn/custom-brainsweep-callback.md) **English**

> Generated by GLM-5.1

## Overview

`BrainsweepCallback` is an extension mechanism provided by HexAutomata that allows you to register custom callbacks for the Brainsweep great spell. When Brainsweep is cast, all matching callbacks are executed in priority order, and the first one to return a non-`null` result determines the final behavior.

## BrainsweepCallback Structure

```kotlin
abstract class BrainsweepCallback<E : Entity, I : Iota>(
    var priority: Int,           // Priority — lower values execute first
    val limitEntity: EntityType<E>?,  // Entity type filter, null means no filter
    val limitIota: IotaType<I>?,      // Iota type filter, null means no filter
)
```

### Core Method

```kotlin
abstract fun call(entity: E, iota: I, env: CastingEnvironment): SpellAction.Result?
```

- Returns `SpellAction.Result?` — returning non-`null` means this callback handled the spell
- Returning `null` means skip this callback and try the next matching one
- Throwing `PatchAction.USE_ORIGINAL` → fall back to original Brainsweep logic
- Throwing `PatchAction.STOP_ALL` → halt the spell

## Using buildResult to Easily Create Return Values

`BrainsweepCallback.buildResult` is a convenience method for quickly constructing `SpellAction.Result`:

```kotlin
companion object {
    @JvmStatic
    fun buildResult(
        action: (CastingEnvironment) -> Unit,  // Action to execute when the spell casts
        cost: Long,                             // Media cost
        vararg particles: ParticleSpray         // Particle effects
    ): SpellAction.Result
}
```

### Example: Using buildResult in Kotlin

```kotlin
import io.yukkuric.hexautomata.action_patch.brainsweep.BrainsweepCallback
import at.petrak.hexcasting.api.casting.ParticleSpray
import at.petrak.hexcasting.api.casting.eval.CastingEnvironment
import at.petrak.hexcasting.api.misc.MediaConstants
import net.minecraft.world.entity.EntityType
import net.minecraft.world.entity.monster.Zombie
import net.minecraft.world.phys.Vec3

object ZombieCallback : BrainsweepCallback<Zombie, Iota>(
    priority = 100,
    limitEntity = EntityType.ZOMBIE as EntityType<Zombie>,
    limitIota = null
) {
    override fun call(entity: Zombie, iota: Iota, env: CastingEnvironment): SpellAction.Result? {
        // Custom condition check
        if (!entity.isBaby) {
            return buildResult(
                action = { _ ->
                    // Execute custom logic on adult zombies
                    entity.setBaby(true)
                },
                cost = MediaConstants.CRYSTAL_UNIT,
                ParticleSpray.cloud(entity.position(), 1.0)
            )
        }
        // Return null to let subsequent callbacks continue processing
        return null
    }
}
```

### Registering a Callback

```kotlin
BrainsweepCallback["my_mod/zombie_baby"] = ZombieCallback
```

The key is a string used to identify the callback. If the key is already taken, an exception is thrown; to override, use `forceSet`:

```kotlin
BrainsweepCallback.forceSet("my_mod/zombie_baby", ZombieCallback)
```

## Registering Callbacks via KubeJS

HexAutomata exposes `BrainsweepCallback` as a KubeJS binding, allowing you to register callbacks directly in server/startup scripts.

### Using the create Method

```js
let myCallback = BrainsweepCallback.create(
    priority,           // Priority (integer)
    entityId,           // Entity type ResourceLocation string, null means no filter
    iotaTypeId,         // Iota type ResourceLocation string, null means no filter
    (entity, iota, env) => {
        // Return SpellAction.Result or null
        if (someCondition) {
            return BrainsweepCallback.buildResult(env => {
                // Spell effect
            }, cost)
        }
        return null  // Continue to subsequent callbacks
    }
);
BrainsweepCallback.forceSet("my_mod/my_callback", myCallback);
```

### Full KubeJS Example

```js
// server_scripts/brainsweep_callbacks.js

let zombieCallback = BrainsweepCallback.create(
    50,
    "minecraft:zombie",     // Only match zombies
    null,                    // No Iota type filter
    (entity, iota, env) => {
        // Set the zombie on fire
        return BrainsweepCallback.buildResult(env => {
            entity.setSecondsOnFire(5)
        }, 1000)  // Costs 1000 media units
    }
);
BrainsweepCallback.forceSet("my_mod/zombie_fire", zombieCallback);
```

```js
// A generic callback with no entity or Iota type restrictions
let fallbackCallback = BrainsweepCallback.create(
    1919810, // Low priority, acts as a fallback
    null,    // No entity type filter
    null,    // No Iota type filter
    (entity, iota, env) => {
        // Log and block the spell
        console.info(`Brainsweep blocked for ${entity.type}`)
        throw PatchAction.STOP_ALL
    }
);
BrainsweepCallback.forceSet("my_mod/fallback", fallbackCallback);
```

### Automatic ID Namespace Remapping

In KubeJS, filter parameters accept string input and automatically convert it to `ResourceLocation`. If the string does not contain a namespace:

- `entityId` defaults to `minecraft:` (Minecraft default behavior)
- `iotaTypeId` is further remapped to `hexcasting:`, supporting shorthand

For example:

- `"zombie"` → entityType looks up `minecraft:zombie`
- `"entity"` → iotaType looks up `hexcasting:entity`
- `"hexcasting:vec3"` → uses `hexcasting:vec3` directly

## Callback Matching and Priority

When Brainsweep is cast, `BrainsweepCallback.callAll()` works as follows:

1. Filter matching callbacks from cache based on the current entity type and Iota type
2. Matching rules: a callback's `limitEntity` and `limitIota` are either `null` or match the current types
3. Sort by priority in ascending order (lower values execute first)
4. Call each in order; the first to return non-`null` determines the result
5. If all callbacks return `null`, fall back to the original Brainsweep logic

## Important Notes

- Lower `priority` values execute first; `Int.MIN_VALUE` is the highest priority, `Int.MAX_VALUE` is the lowest
- Callback results are cached; the cache is automatically cleared when new callbacks are registered
- Throwing `PatchAction.USE_ORIGINAL` or `PatchAction.STOP_ALL` from KubeJS scripts works correctly
- The `action` parameter of `buildResult` receives a `CastingEnvironment`, giving you access to the caster and world information
